# DRUM002 滚筒猫砂盆候选固件

后续版本 DRUM003 已按用户确认的规则实现任一路霍尔感应即可判定集便仓归位，见 [版本与验证记录](SESSION_HANDOFF.md#2026-11-21-drum003-任一路霍尔确认集便仓归位)。以下是 DRUM002 的冻结记录。

2026-11-21。产品为滚筒式，当前暂无滚筒总成。用户确认主板 HLR1/HLR2 用于判断集便仓归位。DRUM002 从 APP004 合版经 DRUM001 增量修改，集便仓霍尔与滚筒位置独立处理。已完成主机回放和 STC32G8K64 目标构建。镜像按未标定状态编译，固件的电机输出保持关闭。DRUM001 产物保留追溯，恢复已实测台架版本使用 APP004。

## 参数与虚拟行程

在 [drum_board.h](../src/DRUM002/drum_board.h) 集中维护原位、各模式目标、去程与回程方向、最大行程、停留时间、键值、集便仓霍尔组合和雷达空闲态。以下数字供主机回放。控制节拍约 9.96 ms。

| 模式 | 虚拟行程 | 每段运动上限 | 目标停留 |
| --- | --- | --- | --- |
| 清理 | P1 原位 → 正转到 P2 排泄位 → 反转回 P1 | 约 20 秒 | 约 1 秒 |
| 平砂 | P1 原位 → 反转到 P0 平砂位 → 正转回 P1 | 约 12 秒 | 约 0.2 秒 |
| 倾空 | P1 原位 → 正转到 P2 倾空位 → 反转回 P1 | 约 20 秒 | 约 5 秒 |

P0～P3 是独立的滚筒位置抽象。P3 表示两标记之间，PF 表示实体滚筒位置未知。H0～H3 是集便仓霍尔引脚的组合，H3 表示两路均高。实板上 H 值变化只影响集便仓判断。集便仓归位的 H 组合待测，实测后填写 `DRUM_BIN_DOCKED_MASK`。接入实际滚筒位置来源后，可以替换行程数字并复用现有流程。

## 功能回归与边界

| 项目 | APP004 与 DRUM002 的对应行为 | DRUM002 的检查 |
| --- | --- | --- |
| 本地按键 | CLEAN 短按启动或暂停/继续，任一键长按约 3 秒取消。保留消抖、上电先松手和长按单次触发。平砂短按、倾空长按均由待标定键号启用 | 主机回放按键和停机。平砂、倾空虚拟行程通过，实体键号待测 |
| 电机和位置 | 改成只从独立位置输入确认的原位出发，经过中间区间和目标位后回原位。目标限位首个样本即撤销驱动，连续 3 个一致样本才切换阶段。目标抖动保持停止，换向前留停机时间 | 三种虚拟行程、去程与回程、限位抖动、异常位置及超时通过。实际位置传感方式、反转、惯性与停机距离待测 |
| 集便仓联锁 | HLR1/HLR2 只用于判断集便仓是否归位，必须在位才能启动。运行中移开会取消任务并撤销驱动，装回不会自动继续 | 主机回放未归位拒绝、运行中取出、装回不自启，以及 H 值变化不改变 P 值。真实归位组合、断线表现和停机时间待测 |
| 三路红外 | 保留载波窗口、三路及采样有效性。首次通过有效通光确认后起动。运动中遮挡或采样失效先撤销输出，连续通光约 10 秒再恢复。暂停、故障和雷达仍可阻止恢复 | 主机边界回放通过。目标汇编核对 TH0 只在初始化写入。整机光路和控制节拍待测 |
| 雷达、复位和故障 | 雷达触发终止任务，清空后只允许从可信原位重新请求。位置、超时及驱动故障锁存。设备启动默认停止，未知位置需要本机处理。保留看门狗与应用期低压复位设置 | 取消、错误原位、无可信传感、驱动故障和重试回放通过。真实雷达断线、低压瞬态及停机安全待测 |
| Wi-Fi 和数据点 | 保留 WBR3、产品标识、心跳、配网和重连流程。DP1 识别 0→1 请求，同值重发不重复启动。DP5 暂停/继续、DP22 独立状态回报。收到 DP12 后回报实际开关，未标定配置回报关闭。DP2 和 DP25 保持解析/诊断，无远程倾空或重启动作 | 真实解析和状态发送入口通过主机回放。当前 DRUM002 的实物配网和手机测试待测 |
| 自动清理 | 已有有效占用→离开倒计时逻辑。默认约 10 分钟，折返或信号失效会重置。用可信的盆内占用输入驱动，雷达原始低电平不当成离盆。恢复供电默认关闭 | 虚拟占用计时、折返和失联通过。实际占用及驱动保护输入尚未接入，量产板采样、安装及阈值待核实 |
| 台架诊断 | 保留状态、霍尔、光路峰值、手动配网和紧急停机。DRUM002 可分开读取集便仓、滚筒位置、阶段、故障和完成计数 | 主机控制入口、协议回放及文件校验通过 |

本版完成计数只在确认回到原位后增加，掉电后清零。静音、童锁、可选延时的数据点、跨断电任务记录及满仓、缺砂与称重等选配功能仍待进一步接入。原理图上的称重和电流采样线路必须与实际生产板、线束、配置交叉核对。仅替换机械参数即可复用行程，保护输入的接入和验收是独立工作。

## VSCode 使用与验证

1. 打开 `litterbox-stc32g.code-workspace`，运行 **猫砂盆 DRUM002: 离线仿真与回归**。可离开主板执行，需要 Python 与 GCC。预期输出虚拟原位 P1、排泄位 P2、回到 P1、完成计数 1，并通过集便仓、平砂、倾空、遮挡恢复、故障、自动倒计时和 DP 回放。
2. 运行 **猫砂盆 DRUM002: 构建滚筒候选固件**。预期输出 `PASS` 和 `output/LB_DRUM002/LB_DRUM002.hex`，校验值与冻结清单一致。离线下载工具回放应记录 224 个写入块，未发送硬件选项写命令。实际回放为软件测试。
3. 后续做主板台架验证时，先断开 12V 并拔下电机，接回霍尔、红外和雷达，CH340 共地且不供电。运行 **猫砂盆 DRUM002: 下载候选固件（电机拔下）**，等待下载器后接回 12V。随后运行 **猫砂盆 DRUM002: 监听滚筒状态与故障**，预期 `DRUM002` 应答，`J=0 F=1 A=0 O=0 Z=0000 B=0 P=F`。原配网仍有效时应回到 `N=04`。用磁铁改变 H0～H3，P 应始终为 F。按下 CLEAN 或 App 启动后观察 `O=0`。失败时保留串口日志并先确认版本、WBR3 下发计数和两个霍尔电平。
4. 整机到位后，电机保持断开。先测集便仓装入、抽出及断线对应的 H 组合，再找滚筒独立位置来源、手动转动滚筒记录标记序列。随后独立核对驱动方向、夹点、停机距离、电流反馈和占用检测。替换实测数字并逐项做有负载、遮挡、折返、卡住和掉电回归。到位、行程与保护全部通过后再开放自动模式。

串口 `B` 为集便仓已确认归位，`P` 为滚筒位置，`J` 为阶段（0 待机，1 去程，2 目标位停留，3 回程），`G` 为模式（0 无任务，1 清理，2 平砂，3 倾空），`O` 为驱动引脚状态，`Z` 为完整回位次数。故障 `F` 枚举为 0 无故障，1 未标定，2 位置，3 雷达，4 超时，5 驱动，6 占用，7 人工取消，8 集便仓未归位。现有手机面板使用既定 DP22 枚举，故障细节先通过串口确认。
