# IR002红外原始验证与后续电机联动

2026-11-10。当前主板仍是已烧入的MOTOR003；IR002仅完成构建和软件检查，尚未下载，模块尚未实测。

## 本轮目标

用户先要求验证照片中红外模块，随后明确：运行时红外触发即停机，最后一次触发后连续10秒无触发才恢复。等待期间再次触发重新计时，手动停机取消恢复；上电不自行启动。实际停止还包含传感器响应、采样和机械惯性，不能用软件禁止输出等同机械瞬停。

目前尚需确认两个探头是面对面对射遮挡触发，还是并排反射触发；不能凭主板NEC丝印猜测协议或有效电平。接收芯片照片没有可读型号，无匹配小板规格书。无型号不判损坏，原始响应不自动代表有猫/无人。

## 资料与布线

照片中三线板VCC/GND/OUT分别接红/黑/黄；两线板T+/T-分别接黄/绿。生产CAM+逐焊盘贴片图核对如下，属于资料连通推断而非实板表测：

厂商STC32G手册PDF第322页说明LQFP48的8脚P1.4、11脚P1.7/PWM4N；1041、1043、1063、1066、1070页分别核对复用、使能、模式、CCER和主输出。原理图GPIO/库中PWM标签不可直接套用。

接收P1.4高阻输入，100us采样；每约500ms报告十六进制S=样本数、L=低电平样本数、E=边沿数；状态另含RAW、TX模式及运行期RSTCFG。无边沿/固定电平只记现象，不直接判故障、读保护或无人。100us内短脉冲可能漏采样。

## 下载流程修正及边界

本机stcgal通用选项写入不再用于IR002。厂商STC32G手册10.3（PDF574～580页）的第三方下载示例在程序写入完成后直接返回，未发送0x04硬件选项写命令。tools/isp_no_options.py在实际stcgal下载路径中跳过program_options，并在发送层禁止0x04，拒绝选项/EEPROM/时钟修改参数，要求原有时钟与11.0592MHz偏差≤0.5%，异常在擦除前停止。

tests/isp_no_options_test.py通过实际安装的HEX解析、主下载流程、STC8d分块/完成/退出实现，传输层离线应答验证无0x04、32个数据块及异常时钟拒绝。握手和真实硬件保持效果未在此测试覆盖；不能把离线测试写成现场通过。

IR002仅运行期依照手册10.5/PDF583页设置RSTCFG：使能低压复位，阈值2.4V，保留复位脚位。它不恢复此前变化的非易失硬件选项；下一次BSL报告是否保持仍须采集核对。旧诊断和产品flash入口继续拦截，仅IR002允许新流程。没有解除读保护，也没有独立固件回读。

## VSCode入口及验证顺序

搜索IR002：构建、离线检查、下载、查询原始状态、测试38kHz短脉冲、关闭发射。统一tools/ir.ps1；固件路径固定上述HEX，记录工具与来源可追溯。

模块实测前：主板12V、CH340 TXD→RX/RXD→TX/GND共地，CH340 VCC不接；电机保持断开，红外按照片原插座接入。新照片的供电/串口口是空的，开始在线阶段时须确认当前状态，不能沿用旧照片假定已连接。不重复回环或无变化参数的断电试验。

待开始在线验证后顺序为：实际下载并核对阶段、只查询身份/STOP/TX0/RST、确认探头安装方式、采集发射关闭基线与有界发射响应，再比较无遮挡/遮挡或远离/靠近，最后确定触发映射。查询和采集成功不能替代模块验收。

tools/ir_status.py先确认IR002身份再允许控制；test38还要求STOP及RST有效配置，关闭2秒→发射10秒→关闭2秒，保留分阶段数据。没有自动判定模块通过。失败先保存build/IR002-*.json和下载日志，核对版本/原始电平/发射模式，再决定单一下一步，不盲目扫参数。

## 10秒恢复逻辑的软件进度

diagnostics/shared/motor_ir_guard.h接收已确认的IR_CLEAR/IR_TRIGGER/IR_UNKNOWN，与用户的运行请求分开计算actual实际输出。触发/未知停止并重计1000个10ms节拍；有效清空连续10秒才允许恢复，手动关闭请求后不自动启动。上电未请求不启动。

tests/motor_ir_guard_test.c通过启动、持续触发、9.99秒/10秒边界、9秒再触发重新计时、手动停机取消、未知状态不计入清空时间等回放。**当前模块未接入主板固件，不宣称红外停机联动已烧录或硬件通过**。后续必须在明确触发方式及实测原始响应后集成新版本，继续继承IR002与MOTOR003行为。
