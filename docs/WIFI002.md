# WIFI002 App 台架验证

2026-11-19，基于 WIFI001 的同一猫砂盆 PID、串口和联网协议。电机拔下，台架仅让 App 改变主控暂停状态。WIFI001 可回退到原联网诊断，IR017 可恢复本地电机和传感器联动。

从产品功能页面核对 DP1 `manual_clean` 手动铲粪、DP2 `empty_cat_litter` 倾空猫砂、DP5 `pause` 暂停/继续、DP12 `auto_clean` 自动铲粪均为 Bool 双向。DP25 `reboot_data` 是 Raw。固件只执行 DP5 的台架状态切换，收到其它 Bool 时记录数据点，不接入执行器。收到合法 DP5 变化后按 0x07 报当前暂停状态，0x08 查询也回当前状态。重复同值不重复改状态，格式错误的整帧不提交。

## 复现

1. 电机拔下、CH340 原样，确认主板当前配网。断开主板 12V，运行 VSCode **猫砂盆 WIFI002: 下载 App 指令联调版**，等下载器显示等待再接回 12V。版本启动后确认联网 `N=4` 且电机位 `O=0`。
2. 运行 **猫砂盆 WIFI002: 监听 App 指令和状态回报**。在真实设备 App 面板点一次暂停，经串口确认 `I=5 U=1 V=1`，再点一次继续，确认 `I=5 U=0 V=0`。`I/U` 是最近的合法 Bool ID/值，`V` 为台架暂停状态，`K` 是状态变化次数，`R` 是主控状态回报帧数。一次点击可能伴随多帧，此轮分别核对变化和回报。
3. 失败时检查 `N`、`D`（合法外层下发帧数）、`X`（DP 格式错误）、`E/T`（串口解析及发送错误）和设备面板功能配置。收到 DP1 或 DP2 只记录来包。故障排查时不要把没有设备动作当成指令没到达。
