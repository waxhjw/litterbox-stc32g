| 操作 | 任务 / 结果 |
| --- | --- |
| 查看工具与串口 | 终端 → 运行任务 → `猫砂盆 STC32G ENV001: 检查环境与串口（不连接主板）` |
| 验证编译环境 | `Ctrl+Shift+B`，运行默认的 `构建环境验证（禁止烧录）` |

本阶段无需把主板接到DAP。检查任务仅枚举USB串口，不打开端口；编译任务在电脑上完成。成功标准为任务终端出现 `PASS` 且退出码0。失败时保留完整终端输出，先检查当前工作区、工具路径及USB识别。

本机中文输入法会拦截 `Ctrl+Shift+B` 并打开表情面板；遇到这种情况，使用“终端 → 运行任务”选择环境验证任务。本工程没有修改系统输入法快捷键。已在本工作区关闭CMake自动配置和缺少CMakeLists提示，避免已有扩展干扰C251工程。

## 已配置工具

- 官方 Keil C251 5.60，独立部署在 `.tools/keil-c251/C251`，保留许可证文件；没有修改原来的 Keil 安装或授权。
- **当前为评估版，限制2KB目标代码**，编译器会保留缺少序列号的警告。完整产品需要合适的正式授权，不能把当前环境当成不受限制的量产编译环境。
- 独立 Python 虚拟环境 `.tools/serial-venv`；stcgal 1.10、pyserial 3.5、tqdm 4.67.1、colorama 0.4.6。
- 当前选择CH340，实际端口COM9，名称 `USB-SERIAL CH340`。任务按配置的USB VID/PID重新枚举，不硬编码COM编号；多只同类设备时拒绝猜选。DAP旧配置与失败记录仅供追溯。
- 当前基础Python来自本机3.9；不作为长期生产环境冻结方案，换电脑重新建立虚拟环境，不直接搬运虚拟环境。

## 环境验证产物

`validation/main.c` 只是空循环，用来实际执行 C251 → L251 → OH251，再用安装的 stcgal 解析HEX。输出在 `build/validation/`，包括HEX、MAP、日志和指纹清单。

**该程序不包含本板初始化、执行器关闭、保护、通信或清理流程，禁止烧入整机。** 编译结果仅证明电脑上的工具链工作，不证明硬件能正常运行或可以安全烧录。

## 导入原程序后才能完成的工作

1. 取得本板完整源码、原Keil C251工程、对应固件、板级配置、编译选项及回滚条件。核对全部既有功能，不能用空工程替代整机程序。
2. 在 `config/project.json` 填写产品 `keil_project`、`target`、`hex`；核实该工程使用正确的C251工具链，当前产品配置保持空值。
3. `uv4` 当前指向已有Keil界面程序；现有Keil尚未集成C251型号和工具路径，导入原工程时必须完成这一步并验证真实产品入口。本阶段独立C251命令行编译已验证。
4. 构建任务会强制重建，检查日志、HEX-386格式、64KB程序地址范围、复位地址及校验值，并生成产品清单。产品下载不会引用环境验证产物。
5. 根据当前板资料核实接线、电平、供电和冷启动条件，再单独验证连接、写入、工具校验、启动及整机回归。

当前使用CH340：`TXD`→主板`RX`，`RXD`←主板`TX`，`GND`↔`GND`，CH340的VCC不接，主板由12V供电。电压未用表实测。生产板四针口SP2：1=主控TX、2=主控RX、3=GND、4=主控电源，来自生产CAM核对；实物方向以丝印为准，不能按照片左右顺序猜针号。

stcgal的下载过程会处理芯片选项和校准，不能宣称“只写程序区”。本次已实际执行MOTOR002/003下载，并发现选项变化，现已暂停项目写入入口。该工具不提供本板原程序的可靠回读备份方案，原厂程序已被诊断版覆盖，不能把连接成功当成已经有回滚文件。
